# 組織図 — パイロット事業部（5体）

既存の `.claude/agents/` のエージェントをそのまま起用する（新規定義は作らない＝上流リポジトリの同期ルールに抵触しない）。
各定時セッションはこの表に従って Task tool（subagent_type）で各社員を起動する。

## メンバー

| 役割 | 起用エージェント | 職務 | 主な読み書きファイル |
|------|-----------------|------|---------------------|
| ①事業部長・戦略 | **haruto** | 週次戦略の決定、タスクの優先順位付け、朝会の司会、改善施策の意思決定 | memory/strategy.md, tasks/backlog.md |
| ②商品開発 | **kotone** | テンプレート商品（P1〜P3）の企画・執筆。訴求軸・コピー設計の知見を商品化 | tasks/, 商品ドラフト（products/配下に出力） |
| ③集客・マーケ | **sho** | X投稿・note記事のドラフト作成（毎日）。トーンは「親しみ×信頼」 | tasks/, 投稿ドラフト（drafts/配下に出力） |
| ④分析 | **shun** | 投稿・商品ページ・売上データの週次分析。「何が効いて何が効いてないか」を数値で報告 | ledger/*.csv, memory/learnings.md |
| ⑤経理・帳簿 | **finance** | 帳簿（ledger/）の整合性チェック、週次PL、コスト監視、KPI集計の正確性担保 | ledger/*.csv |

## 指揮系統と1日の流れ

```
HARU（人間）
  └─ 承認のみ（公開・販売・支出）
haruto（事業部長）
  ├─ 朝会: backlog を確認し、当日タスクを kotone / sho に割り当て
  ├─ 夕会: 成果物を検収し、[承認待ち] として backlog に登録
  └─ 金曜: shun の分析 + finance の週次PL を受けて strategy.md を更新
kotone ──→ 商品ドラフト ──→ haruto 検収 ──→ HARU 承認 ──→ 販売開始
sho ─────→ 投稿ドラフト ──→ haruto 検収 ──→ HARU 承認 ──→ 公開
shun / finance ──→ 週次レポート ──→ haruto（改善判断の材料）
```

## 権限（ガードレール）

- 全員: `pilot-company/` 配下の読み書きは自由。`.claude/agents/` の編集は禁止
- 対外公開・販売開始・支出の**実行権限を持つのは HARU のみ**。AIは「承認待ちキューに積む」まで
- 検収で差し戻す場合、haruto は具体的な修正指示を backlog に書く（口頭NG禁止）
