# AI社員パイロット事業部（1ライン・5体構成）

「AI社員が働き、実際に稼ぎ、売上データを見て自分で改善する会社」の最小実証ユニット。
このディレクトリが事業部の**オフィス兼帳簿兼記憶**です。すべて git 管理し、AIセッションが読み書きします。

## ディレクトリ構成

```
pilot-company/
├── README.md            # このファイル（事業部の入口）
├── BUSINESS_PLAN.md     # 事業計画：何で稼ぐか・KPI・目標
├── ORG.md               # 組織図：5体の役割と既存エージェントへのマッピング
├── OPERATIONS.md        # 運用マニュアル：9:00-18:00 の稼働設計と起動方法
├── prompts/             # 定時起動用プロンプト（cron / launchd / Routines から使う）
│   ├── morning.md       # 9:00  朝会・タスク割り当て・制作実行
│   ├── midday.md        # 13:00 進捗確認・制作継続・集客コンテンツ作成
│   ├── closing.md       # 17:30 終業処理・日報・帳簿更新・commit & push
│   └── weekly-review.md # 金曜  週次分析・改善会議（マネタイズ結果→戦略更新）
├── ledger/              # 帳簿（データ基盤の出発点。将来 Sheets / Stripe 連携へ移行）
│   ├── sales.csv        # 売上台帳
│   ├── costs.csv        # 経費台帳（API利用料・広告費など）
│   └── kpi_weekly.csv   # 週次KPI（集客・CV・売上）
├── memory/              # AI社員の記憶（学習した内容はここに蓄積）
│   ├── strategy.md      # 現在の戦略（週次レビューで更新される「経営方針書」）
│   └── learnings.md     # 学んだこと・失敗・市場の反応の記録
└── tasks/
    └── backlog.md       # タスクキュー（仕事の源泉。人間もAIもここに追加）
```

## 動かし方（クイックスタート）

1. **人間がやること（初回のみ）**
   - 販売プラットフォームのアカウント準備（note / Brain / Stripe Payment Link のいずれか）
   - SNS発信用アカウントの用意（X / Instagram いずれか1つでOK）
   - スケジューラ設定（`OPERATIONS.md` 参照。既存の launchd 運用の延長で可）

2. **毎日自動で回るループ**
   - 9:00 / 13:00 / 17:30 に `claude -p "$(cat pilot-company/prompts/xxx.md)"` が起動
   - AI社員がタスク実行 → 成果物と承認依頼を出力 → 帳簿・記憶・日報を更新して push

3. **人間の役割（毎日5〜15分）**
   - 承認キュー（`tasks/backlog.md` の `[承認待ち]` 項目）を確認して公開・販売ボタンを押す
   - 売上が発生したら `ledger/sales.csv` に1行追記（初期のみ手動。自動化はPhase 2）

## 人間承認が必須のライン（変更禁止のガードレール）

- 対外公開（SNS投稿・記事公開・商品販売開始）は**必ず人間の承認後**
- 支出（広告費・有料ツール）は**事前承認なしに実行しない**
- 契約・請求・返金対応は人間が行う
