# 書き込み経路の設計判断（403問題）

- 記録日: 2026-07-09
- 検証者: 対話セッション（HARU立会いのやり取り内）

## 検証で確定した事実

| 主体 | git push | GitHub MCP | 結論 |
|------|:--------:|:----------:|------|
| Mac（launchd） | ✅ 成功（`x-bot: post` コミットが証拠） | 未使用 | **書ける** |
| 対話セッション（claude.ai/web） | ✅ 成功 | ✅ 成功 | **書ける** |
| クラウド無人セッション（cron発火） | ❌ 403 | ❌ ツールに無い | **書けない** |

→ 朝会Routineを発火テストしたが、29分後も main にコミットされず（`morning:` 無し）。無人セッションは生成しても保存できないと確定。

## 対策（プロンプトは万能化済み）

4プロンプトの終了処理を「①git push を試す → ②403ならGitHub MCPにフォールバック」に統一。
これで Mac でも対話セッションでも書き込みが通る。

## 決定: 案A（Mac一元化）— 2026-07-09 HARU選択

Macのlaunchdで `claude -p` を実行し生成もMacで行い、Macのgitでpushする。クラウドの無人Routineは停止済み。
セットアップ: `pilot-company/orchestrator/setup_orchestrator.sh`（Macで実行）。

## 参考: 検討した2案

### 案A: Mac一元化（最も堅牢・推奨）
- Macのlaunchdで `claude -p "$(cat pilot-company/prompts/xxx.md)"` を実行し、生成もMacで行う。書き込みはMacのgit push（成功実績あり）
- クラウドRoutineは廃止（または通知専用）
- 準備: Macに Claude CLI を導入し1回ログイン（Claudeサブスクで可・API課金不要）。launchdに4ジョブ（朝/昼/終業/週次）追加
- 長所: 403の起きようがない・完全自律・Mac一箇所で完結
- 短所: 初回セットアップ（CLI導入・auth）が要る

### 案B: 対話セッションに自己バインド（セットアップ最小）
- 4つのRoutineを「新規セッション発火」から「このセッションに自己バインド」へ変更。発火時に書き込み権限を持つ本セッションが再開して実行
- 準備: ほぼ不要（Routine再作成のみ）
- 長所: Mac作業ゼロ
- 短所: 同一会話にコンテキストが蓄積し肥大化・長期安定性が案Aに劣る
